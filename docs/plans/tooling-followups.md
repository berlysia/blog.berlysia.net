# Tooling follow-ups

Left over from the oxlint/oxfmt, TypeScript 7 and Tailwind CSS v4 migration.

## Turn on `strict` in tsconfig

`tsconfig.base.json` sets `"strict": false` explicitly because TypeScript 7 enables strict by default and the code was written without it. Enabling it reports 19 errors (null checks in `app/lib/ogCache.ts`, `app/honox/ResolveManifest.tsx`, `app/islands/Tweet.tsx`; implicit `any` in `app/islands/Image.tsx`; unified plugin typings in `app/lib/mdx/utils.ts`; and a few more). Run `pnpm exec tsc --noEmit --strict` to list them.

## Rules lost with ESLint

`.oxlintrc.json` was generated by `@oxlint/migrate` from `@berlysia/eslint-config`. These were dropped because oxlint has no equivalent or they came from JS plugins:

- `@berlysia/prefer-closest-import-path` (from `@berlysia/eslint-plugin`)
- `eslint-comments/*`, `jsonc/*`, `markdown/*`
- rules `@oxlint/migrate` lists as not implemented (run `pnpm dlx @oxlint/migrate --details` against the old config from git history to see them)

Decide whether any of them should come back through oxlint `jsPlugins`.

## Tailwind CSS v4 leftovers

- The build prints a Lightning CSS warning that `::column` is not a known pseudo-element (`app/style.css`, multi-column vertical layout). The rule still ships; check that it keeps working in the browsers you target.
- `keyColor` now follows the v4 pink palette (oklch), which is slightly more saturated than the v3 hex values. Pin the v3 hex values in `@theme` if the old tone is preferred.
